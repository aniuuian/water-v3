# 2026-08-14 · 字体卡顿复发 → 本地自托管根治

## 现象
用户再次反馈 Chrome 打开本地页一直加载转圈。排查发现：design-system.css 第6行又被写回阻塞 `@import`（且字体族被改成 Space Grotesk / Instrument Serif / Inter / JetBrains Mono）；8/10 注入的非阻塞 Google Fonts 块也被覆盖丢失。根因同前：render-blocking 的 Google Fonts @import，用户网络对 fonts.googleapis.com 不可达。

## 根治方案（本地自托管，彻底甩外部依赖）
- 用脚本 /tmp/download_fonts.js：模拟浏览器 UA 请求 Google Fonts css2，仅取 latin 子集 woff2，下载到 assets/fonts/（16 个文件：Space Grotesk 300-700、Instrument Serif normal+italic 400、Inter 300-800、JetBrains Mono 400-600），并生成 assets/css/fonts.css（16 条 @font-face，src 指向本地）。
- 删除 design-system.css 的 @import（第6行改为注释警告，说明不要再加阻塞 @import）。
- 用 /tmp/inject_fontcss.js 给全部 22 个 html 的 </head> 前注入 `<link rel="stylesheet" href="assets/css/fonts.css" />`。
- 用 /tmp/clean_googleapis.js 清理残留的 Google Fonts 外链（5 个页面）。

## 关键认知
- 用户 Chrome 网络在 GFW 后，fonts.googleapis.com 不可达 → 之前"非阻塞异步"方案下，用户本地永远加载不出设计字体（只能看系统字体兜底），且若用 @import 会阻塞整页。
- 沙箱(WorkBuddy)网络可访问 Google → 由沙箱下载字体到本地，用户 Chrome 走 127.0.0.1 本地路径，不受墙影响，秒开且显示真实设计字体。
- 这是根治：无论用户网络如何、design-system.css 是否被重做，只要 HTML 仍引用 fonts.css、字体变量名不变，字体即本地可用。复发风险点仅剩：有人重写 design-system.css 且加回 @import 或删掉 fonts.css 引用。

## 验证
- 全站无 fonts.googleapis.com 外链；22 页引用 fonts.css；woff2 经服务器返回 200；pages 冒烟 200。
- 提醒用户硬刷新（Cmd/Ctrl+Shift+R）绕过浏览器对旧 CSS 的缓存。
